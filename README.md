# Kepler Flight Lab · Этап 1

Лётная песочница для **Unity 6.0 LTS / URP**, стартующая на солнечной стороне Земли. На высоте **420 км** отпустите управление: даже при нулевой тяге аппарат летит относительно Земли со скоростью **7,661 км/с**. Это состояние интегратора, а не анимация по заданной окружности. `↑` добавляет тягу вдоль носа, `X` выключает двигатель, но не обнуляет скорость.

## Сборка игры на Linux x86_64

На Linux установите через Unity Hub **Unity Editor 6000.0.40f1** с поддержкой настольного Linux Player (Mono; на Linux обычно входит в Editor) и активируйте лицензию. Для первого импорта нужен доступ к Unity Package Registry. Закройте Editor, если в нём открыт этот проект. Распакуйте исходники релиза или клонируйте репозиторий и из корня выполните:

```bash
./scripts/build-linux.sh
```

Скрипт находит редактор в `~/Unity/Hub/Editor/6000.0.40f1/Editor/Unity`. Для нестандартной установки: `UNITY_EDITOR="/полный/путь/Editor/Unity" ./scripts/build-linux.sh`. Он генерирует сцену, выполняет проверки этапа 1 и вызывает Unity BuildPipeline для `StandaloneLinux64`. Отдельно открывать сцену или нажимать Build Space Game не нужно. Лог: `Builds/linux-build.log`. После успешной сборки запустите игру в графической сессии:

```bash
tar -xzf Builds/Kepler-Linux-x86_64.tar.gz
./Kepler-Linux-x86_64/Kepler.x86_64
```

Архив из `Builds/` можно перенести на другой Linux x86_64 с графическим драйвером: для **запуска** Unity Editor не нужен, но исполняемый файл должен оставаться рядом с каталогом `Kepler_Data`, `UnityPlayer.so` и остальными файлами архива.

## Запуск с чистого диска

1. Установите **Unity Hub и Unity Editor 6000.0.40f1** (или совместимый патч 6000.0 LTS). Для Play Mode модуль сборки плеера не нужен.
2. В Hub нажмите **Add → Add project from disk** и выберите **корень репозитория** — папку, внутри которой лежат `Assets`, `Packages` и `ProjectSettings`. Это уже проект, копировать скрипты в сцену не надо.
3. Откройте проект и дождитесь импорта. Package Manager читает `Packages/manifest.json` автоматически. Если восстанавливаете зависимости вручную, откройте **Window → Package Management → Package Manager → + → Install package by name** и установите:

   | Официальный пакет | Версия |
   |---|---|
   | `com.unity.render-pipelines.universal` | 17.0.3 |
   | `com.unity.inputsystem` | 1.11.2 |
   | `com.unity.burst` | 1.8.18 |
   | `com.unity.mathematics` | 1.3.2 |

   C# Job System входит в Unity; Collections разрешается зависимостями URP. UI — встроенный **UI Toolkit**. Платные ассеты, Cinemachine и VFX Graph не нужны. New Input System выбран в `ProjectSettings/ProjectSettings.asset`. Если при переносе в другой проект Unity попросит активировать новый input backend, подтвердите и дождитесь перезапуска.
4. Вне Play Mode выберите **Tools → Build Space Game**. Билдер откроет `Assets/KeplerGenerated/SolarFlight.unity` и поставит сцену первой в Build Settings. Если открытая сцена изменена, сначала появится обычный запрос Unity о сохранении.
5. Нажмите **Play** и щёлкните в окне **Game**. На старте должны появиться земной горизонт, корабль и телеметрия. Чтобы проверить сборку и численные инварианты, выйдите из Play Mode и выберите **Tools → Verify Space Game**.

**Что делает кнопка.** Создаёт URP Asset и Forward Renderer, назначает pipeline проекту и текущему уровню качества, заводит слои `KeplerScaled` и `KeplerLocal`, теги `Spacecraft` и `CelestialBody`, создаёт материалы, меш сферы, префабы корабля и тела, ассеты десяти небесных тел, настроек, корабля и двигателя. Генерирует `PilotControls.asset` (InputActionAsset), Panel Settings и тему; выставляет свет, камеры, начальные положения и связи HUD. Повторная сборка использует те же пути, не размножает слои или записи сцены. **Сгенерированная сцена, префабы, каталог и привязки пересобираются**: свои варианты сохраните отдельно. Для штатного повторного запуска достаточно Play.

**Вручную остаются:** установить и активировать Editor, разрешить загрузку Unity-пакетов при первом открытии, при необходимости подтвердить перезапуск, нажать Build Space Game и Play. Для самостоятельного исполняемого файла отдельно установите модуль нужной платформы в Hub и используйте **File → Build Profiles → Build**. Вручную размещать GameObject, настраивать инспекторы, слои или камеры не требуется.

## Управление

| Действие | Клавиатура | Геймпад |
|---|---|---|
| Тангаж / рыскание | W, S / A, D | правый стик Y / X |
| Крен | Q, E | левый стик X |
| Увеличить / уменьшить дроссель (положение сохраняется) | ↑ / ↓ | левый стик Y |
| Отсечка тяги | X | южная кнопка |
| Следующее небесное тело | Tab | RB |
| Смотреть на цель / вернуться за корабль | C | LB |
| Пауза / продолжить | P | Start |
| Вернуть всю систему и корабль в начальное состояние | R | Select |

Кнопки HUD дублируют навигацию, паузу и сброс. Высота — от средней сферической поверхности ближайшего тела, скорость — относительно его центра (без вращения поверхности), дальность до цели — до её **центра**. Выбор цели не меняет систему отсчёта телеметрии и не телепортирует корабль. При пересечении радиуса тела симуляция останавливается; `R` возвращает на старт. Это пока не посадка.

## Архитектура и файлы

Поток данных: **ScriptableObject → начальные векторы в СИ → фиксированные шаги физики → относительные координаты → две камеры URP и HUD**. `Transform` не служит источником орбитальных состояний. Внутренняя иерархия задаёт только начальные элементы относительно родителя; после старта действует взаимное тяготение без привязки планет к Transform Солнца.

| Путь относительно `Assets/` | Ответственность |
|---|---|
| `Scripts/Core/Flight.cs` | Жизненный цикл симуляции, накопитель времени, ввод, пауза, сброс и интерполяция для изображения |
| `Scripts/Universe/{BodyData,InitialOrbit,SolarStart}.cs` | Физические данные, решение уравнения Кеплера, переход к барицентру, стартовая орбита |
| `Scripts/Physics/GravityWorld.cs` | Постоянные NativeArray, суммирование ньютоновских ускорений в Burst IJobParallelFor и kick–drift–kick Velocity Verlet |
| `Scripts/Ship/{ShipData,EngineData,Helm}.cs` | Постоянная масса, главные моменты инерции, уравнения Эйлера, единичный double-кватернион, управляющие моменты с демпфированием и тяга через центр масс |
| `Scripts/Settings/FlightSettings.cs` | Шаг, предел подшагов, стартовое тело и высота, seed оформления неба |
| `Scripts/Camera/FlightRig.cs` | Фоновая Base Camera и локальная Overlay Camera, обзор цели, направление солнечного света |
| `Scripts/Rendering/GlobeMesh.cs`, `Shaders/{World,Sky}.shader` | Общий cube-sphere, процедурные цвета, освещение и звёздное небо |
| `Scripts/UI/FlightHud.cs`, `Interface/Flight.{uxml,uss}` | Представление данных, разметка и стили UI Toolkit |
| `Scripts/Editor/{SpaceBuilder,SolarCatalogue,FlightChecks}.cs` | Построение проекта, числовой каталог, проверки сцены и интегратора |

**Система отсчёта.** Положение и скорость — барицентрические `double3`. Локальное начало каждый кадр совпадает с кораблём: сначала в double вычитается позиция корабля, затем результат преобразуется во float. Дальняя камера рисует небесные тела с одинаковым коэффициентом для радиусов, позиций и смещения наблюдателя: **1 единица = 1000 км**. Локальная камера рисует корабль в метрах поверх фона с очисткой глубины. Угловой размер тел сохраняется; далёкая планета действительно может быть меньше пикселя.

**Физика.** По умолчанию шаг 0,04 с; на каждом шаге ускорения пересчитываются после переноса позиций. Для 11 состояний Burst-job исполняется через `Run`, чтобы не синхронизировать worker-потоки ради сотни взаимодействий; для 64+ — через `Schedule`. Корабль — пробная частица: испытывает тяготение всех тел, но не возмущает их орбиты. Тяга на подшаге постоянна. После долгой задержки накопитель ограничен шестью подшагами: симуляция отстанет от настенных часов, но не совершит один огромный скачок. Массивы переиспользуются и освобождаются при уничтожении сцены. Строки телеметрии форматируются таймером панели в 5 Гц, а не в физическом цикле. 60 FPS — цель для профилирования в плеере, не измеренный результат.

**Исходные данные.** Массы в кг, средние радиусы в метрах; `SolarCatalogue` переводит большие полуоси из а.е. в метры. Для планет взяты приближённые средние элементы на J2000 из [JPL, Approximate Positions of the Planets](https://ssd.jpl.nasa.gov/planets/approx_pos.html). Элементы барицентра Земля–Луна использованы как приближение для Земли; Луна инициализирована отдельной средней геоцентрической орбитой. Это учебная модель, не эфемериды DE440, не положение планет на сегодняшнюю дату. Рисунок континентов и облаков синтетический.

## Как проверить

- **Численно:** `Tools → Verify Space Game` проверяет скорость и высоту старта, скорость барицентра, шаги N-body, разгон постоянной силой, движение по круговой орбите за период (радиус, замыкание орбиты и энергия), наличие управления, ресурсов HUD и непересекающиеся слои камер. Ошибка вызывает исключение, успех выводится в Console.
- **В полёте:** дайте тягу до 50 %, отпустите клавишу, попробуйте тангаж и крен, затем отсечку. При отсечке дроссель должен стать нулевым, аппарат продолжит движение по инерции. `P` замораживает часы. `Tab` меняет цель, `C` направляет камеру на неё, `R` возвращает исходные значения. Нажатие `Build Space Game` второй раз должно создать тот же состав сцены.
- **Пакетная проверка с установленной Unity** (закройте интерактивный Editor для этой папки):

  ```sh
  "$UNITY_EDITOR" -batchmode -quit -projectPath "$PWD" \
    -executeMethod Kepler.Editor.FlightChecks.BuildAndVerify -logFile -
  ```

## Граница этапов

1. **Реализовано здесь:** однокнопочная сборка, настоящие масштабы и начальные орбиты Солнечной системы, N-body, лётное управление, тяга с расходом топлива и ограниченный осевой конструктор, floating origin, scaled space, две точки наблюдения, базовый HUD. Нет Rigidbody, фиктивного time warp или предзаписанного движения.
2. **Следом — навигация:** вычисление орбитальных элементов из текущих `r,v`, карта, прогноз траектории, узлы манёвров; затем переходы между N-body и движением на рельсах и проверка точности при ускорении времени.
3. **Двигатели и конструкция:** начальный осевой конструктор, топливо, Isp и delta-v добавлены; центр масс из геометрии, ступени и автономные системы остаются на будущее.
4. **Приближение к поверхности:** атмосферы, нагрев, столкновения, посадочные опоры, адаптивные тайлы рельефа. Сейчас поверхность — гладкая сфера постоянного разрешения с шейдерной окраской, без LOD, атмосферной физики и затмений.
5. **Вселенная:** генерация систем и галактик, чёрные дыры, релятивистика, исследование, меню настроек и профилирование. Сейчас доступна одна система; seed меняет рисунок звёздного фона при сборке, а не физический каталог.

### Экспериментальная карта и варп

В панели навигации нажмите «Карта» и выберите тело из списка. Это схематический вид сверху: радиальный масштаб логарифмический, поэтому углы и расстояния нельзя измерять линейкой; белый треугольник — корабль. Кнопка тестового варпа перемещает его к выбранному телу, время вычисляется по расстоянию и условной скорости 10 млрд м/с. По прибытии задаётся идеализированная круговая орбита; препятствия на пути не моделируются; используется условный расход топлива. Планеты продолжают двигаться. Пауза останавливает перелёт, сброс отменяет его. Это игровой прототип, а не физическая модель варп-двигателя. Для варпа нужен установленный модуль и достаточно топлива.

В реальных ракетных двигателях расход рабочего тела зависит от тяги и удельного импульса: [NASA: Specific Impulse](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/specific-impulse/). Концепция Алькубьерре является теоретической геометрией пространства-времени, не готовым двигателем: [Alcubierre, 1994](https://arxiv.org/abs/gr-qc/0009013).

### Меню, обзор и настройки

При запуске показывается меню; «В полёт» продолжает симуляцию. Escape открывает меню или закрывает карту. В настройках сохраняются чувствительность мыши, вертикальная синхронизация и полноэкранный режим. В полёте удерживайте правую кнопку мыши и двигайте мышь для обзора корабля, колёсико изменяет расстояние. На карте ПКМ вращает схематический вид, колёсико меняет масштаб; Солнце находится в центре. Линии — наглядные окружности по текущим расстояниям, а не расчётные орбиты. Масштаб логарифмический. Пока открыта карта, управление кораблём с клавиатуры заблокировано, но симуляция и варп продолжаются; меню останавливает симуляцию.

Планеты пока имеют видимую сферическую поверхность с процедурной окраской, но геометрического рельефа, посадки и перемещения по поверхности нет: контакт со сферой останавливает полёт. Ограничения конструктора описаны ниже.


### Конструктор корабля

В главном меню выберите «Конструктор корабля». Добавляйте баки, химические и ионные двигатели, блоки РСУ и варп-модуль кнопками; стрелками меняйте порядок, крестиком удаляйте. Кабина закреплена в носу; всего можно установить до 12 деталей. «Сохранить и начать полёт» сохраняет проект локально и **начинает полёт заново с полными баками**. Отмена не изменяет корабль. В полёте открыть конструктор можно через меню.

Показываются масса, запас топлива, тяга, эффективный Isp и идеальная Δv. Двигатели работают одновременно и берут топливо из общего бака; тяга исчезает, когда оно заканчивается. РСУ управляет вращением и тоже расходует топливо, без неё или топлива вращать корабль нельзя. R сбрасывает полёт и заправляет баки. Варп требует модуль и расходует 50 кг плюс 0,1 кг на каждые 10 млрд метров до центра цели — это игровое допущение, не научная модель.

Это **простой осевой конструктор**, не свободное 3D-размещение: нет ступеней, отдельных топливных контуров, баков разных веществ, перетоков, центра масс из геометрии или линейных сопел РСУ. Ионный двигатель здесь условный: его тяга завышена для игрового баланса, питание и запас энергии не моделируются. Моменты инерции приблизительно масштабируются с массой. Все детали создаются автоматически через Tools → Build Space Game и хранятся как ScriptableObject в `Assets/KeplerGenerated/Modules`.

### Прототипы баков для будущего отдельного конструктора

`Tools → Build Space Game` (или отдельно `Tools → Build Tank Prototypes`) создаёт в `Assets/KeplerGenerated/Tanks/` четыре **прототипа**: цилиндрический, сферический, с куполами и баллон РСУ. Каждый содержит три процедурные сетки, `LODGroup`, выпуклый `MeshCollider` по упрощённой сетке, шесть `AttachNode` и `TankDefinition` с габаритами, геометрическим объёмом, заданной сухой массой и массой топлива. Узлы пока только данные: snap, проверки пересечений и отдельная сцена ещё не реализованы. Эти префабы пока не связаны с действующим осевым конструктором и не включаются в игрока как детали корабля.

Размеры, массы и материалы этих прототипов условные: это не копии Falcon 9, Saturn V, шаттла или МКС. Используется однотонный URP Lit с Metallic/Smoothness; фототекстур, нормалей, AO, маркировок, сварных швов и HDRI здесь нет. NASA описывает внешние баки шаттла как сварные алюминиевые секции с эллиптическими крышками и теплоизоляцией: [NASA NTRS](https://ntrs.nasa.gov/api/citations/20060056194/downloads/20060056194.pdf). Эту информацию нельзя считать готовой моделью или лицензией на текстуры.

Чтобы добавить ещё один *прототип* в автоматический генератор, добавьте вызов `Make(...)` в `Assets/Scripts/Editor/TankAssetBuilder.cs`: укажите уникальный ID, название, форму, радиус и высоту в метрах, сухую массу и массу топлива в килограммах, цвет и metallic. При следующей генерации будут созданы меши, материал, префаб и ScriptableObject. Объём рассчитывается геометрически и не выводится из указанной массы топлива. Для новой формы потребуется расширить `TankShape` и профиль в `TankMesh.Create` и формулу `TankMesh.Volume`. Генерируемые файлы не редактируйте вручную: генератор перезаписывает их.

### Основа будущего конструктора

`Assets/Scripts/Builder/ConstructionGraph.cs` содержит отдельную модель соединённых деталей: соединение совместимых свободных узлов, расчёт положения относительно родителя, каскадное удаление, Undo/Redo и экспорт/валидацию JSON в памяти. При загрузке позиции вычисляются из узлов заново; неверный документ не заменяет текущий. Для этой модели добавлены проверки в `Tools → Verify Space Game`.

Это пока **не отдельная сцена и не пользовательский конструктор**: модель нигде не подключена к интерфейсу или полётной сцене, не проверяет пересечения и не реализует симметрию, перетаскивание, файл сохранения или запуск корабля. Она пока работает только с существующими `TankDefinition`. Прототипы не получили фототекстур. Лицензия [ambientCG CC0](https://docs.ambientcg.com/license/) проверена, но сами карты в проект не загружены.
